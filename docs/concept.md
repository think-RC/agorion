# Concept

## 社会課題を中心に置く

現代には、ニュース、SNS、行政資料、統計、論文、国会・地方議会の記録、パブリックコメント、政党資料、政治家の発言など、大量の情報があります。

しかし、それらは記事、投稿、文書、出来事の単位に分散し、社会課題そのものを中心に整理されていません。一時的な話題性やニュース性が強い情報に注目が集まり、長期的に重要な課題が埋もれることもあります。

Agorion は、情報を記事単位で並べるのではなく、社会課題へ結び直します。

```text
ニュース・行政資料・統計・論文・議会資料
                        ↓
                     社会課題
                        ↓
            論点・関係・政策・市民認識
```

## 課題を「カルテ」として扱う

出来事は時間とともに流れていきます。Agorion では、出来事を継続的に更新される社会課題の履歴へ吸収します。

一つの課題について、次の問いをたどれる状態を目指します。

1. 何が起きているか
2. なぜ起きているか
3. 誰にどのような影響があるか
4. 何が論点か
5. どのような対応や政策があるか
6. 社会がどの程度問題だと認識しているか

## 議論マップを中心にする

Agorion の中心的な役割は、課題についての情報を並べることだけではなく、議論を構造化し、継続的に深められるマップを育てることです。

```text
社会課題
 ├─ 事実・状況と根拠
 ├─ 論点
 │   ├─ 主張
 │   ├─ 反論
 │   └─ 未解決点
 ├─ 対応方針と代替案
 └─ 支持、社会の応答、実施結果
```

新しい情報や意見が加わるたびに、不足する根拠、衝突する前提、未回答の反論、見落とされた影響や代替案を確認します。議論を深めるとは投稿数を増やすことではなく、何が確認され、何が争われ、何が未解決なのかを明確にすることです。

利用者は「この意見を支持する」「反対する」「条件付きで支持する」「まだ判断できない」と表明できます。これらは、支持が集まる主張だけでなく、意見が分かれる条件や深めるべき反論を見つけるために使います。

## 市民認識と事実を分ける

市民が「問題だと思う」と意思表示できる仕組みを構想しています。ただし、票の多さを真実や客観的重要性とは扱いません。

- 市民の意思表示は、社会の認識を示すシグナル
- 資料や統計は、検証可能な根拠
- 因果関係は、根拠付きの構造的な主張

この三つを分けて表示することが重要です。

## 支持を社会的対応シグナルへつなぐ

議論マップの中で具体的な対応方針が比較できるようになったら、市民は「この方針を支持する」と意思表示できます。支持の対象は政治家個人ではなく、誰に何を求めるのかが明確な方針です。法改正だけを前提にせず、行政運用、予算、監査、情報公開、インフラ、民間慣行、追加調査なども選択肢に含めます。

議論内の「この意見を支持する」は、自動的に社会への要請にはなりません。対応内容を具体的な方針として整理し、その内容を確認したうえで行う「この方針を支持する」という別の意思表示だけを、社会的対応シグナルの支持集計に用います。

支持が一定の広がりを持ち、主要な根拠、反論、代替案、未解決点が整理された場合、その状態を社会的対応シグナルとして示します。シグナルには、支持数だけでなく、求める対応、要請先、根拠、主な反対意見、残る不確実性、集計範囲を含めます。

これは議論の終了や社会全体の合意を宣言するものではありません。社会へ対応を求め、その応答、実施、効果、副作用を再び議論マップへ戻すための接続点です。方針が実質的に変わった場合は、以前の支持を自動的に引き継がず、改めて確認します。

## 個別政策を裁定しない

Agorion は、民主的意思形成、透明性、根拠、検証可能性、説明責任、多元性を支持します。一方で、特定政党や個別政策をAgorion自身の結論にはしません。

異なる政策案、価値観、立場が存在することを前提に、それぞれの根拠、反論、影響、トレードオフを理解できる状態を目指します。社会的対応シグナルは、Agorion運営が個別政策を正解として支持するものではなく、参加者の支持と議論の到達状態を透明に伝えるものです。
